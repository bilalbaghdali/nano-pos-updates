# NANO POS v1.0.52 — لا دخول قبل اكتمال التأثير

**نُشر في 13 أكتوبر 2026 · تحديث اختياري**

## ما أصلحته
- في v1.0.51 كان فرع نجاح تسجيل الدخول يكتب `pos_current_user` ويخفي `loginOverlay` **قبل** انتظار تأثير التحقق، ولذلك قد تظهر الصفحة الرئيسية قبل اكتمال التأثير.
- في الإصدار v1.0.52 أصبح الترتيب ثابتًا:
  1. يتحقق `loginUser` من صحة اسم المستخدم وكلمة المرور.
  2. يظهر تأثير دائرة التقدم وعلامة النجاح الخضراء ويكتمل.
  3. **بعد انتهاء التأثير فقط** يحفظ البرنامج هوية المستخدم ويُخفي نافذة الدخول.
  4. يبدأ `initUserSession()` وتظهر الصفحة الرئيسية.
- إذا كانت كلمة المرور خاطئة، لا تعمل حركة النجاح.
- إذا كانت ملفات الحركة مفقودة أو تعطلت، يظل نموذج تسجيل الدخول ظاهرًا بدل الدخول دون التأثير.
- لا تغيير على الصلاحيات أو كلمات المرور أو البيانات أو الوظائف الأخرى.

## الفحوصات
- اختبار تأجيل الجلسة حتى حل Promise الخاص بالحركة: **نجح**.
- اختبار غياب الحركة: لا يفتح البرنامج: **نجح**.
- اختبار حدوث خطأ أثناء الحركة: لا يفتح البرنامج: **نجح**.
- اختبار عرض دائرة التقدم ومرحلة النجاح عند اعتماد صحيح، وعدم ظهورها عند رفض الدخول: **نجح**.
- إعادة بناء `app.asar` من إصدار v1.0.51 المنشور مع تثبيت بصمة أساس التحديث.
- تطابق SHA-256 للملف الذي أعيد تنزيله من GitHub، ونجاح GitHub Actions.
- **تنبيه:** لم يُجر اختبار بصري نهائي على برنامج Windows فعلي، وتعذّر اختبار Chromium محليًا في بيئة التنفيذ.
