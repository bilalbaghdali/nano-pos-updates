# Nomad POS v1.2.20 — الانتقال الآمن عند فقدان مفتاح توقيع APK

**الحالة: خطة ترحيل ومسودة بناء، وليست نسخة APK منشورة.** لا تفعّل بيان `nomad-android/latest.json` قبل نجاح اختبارات البيانات والتفعيل والتثبيت على هاتف فعلي.

- بصمات شهادات 1.2.17 و1.2.18 و1.2.19 مختلفة؛ لم يُعثر على مفتاح 1.2.19 الخاص في مصادر المشروع المتاحة، وأفاد المالك بعدم العثور عليه محليًا.
- لا يمكن إجراء تحديث Android طبيعي لحزمة مثبتة بتوقيع جديد؛ الحفاظ على بياناتها يتطلب ترك القديمة مثبتة وتثبيت **حزمة جديدة منفصلة** مؤقتًا.
- نسخة مصدر الترحيل تستعمل `applicationId=com.nanopos.nomad.stable` وعنوان `Nomad POS - Stable`، مع إصدر 1.2.20 ومدير تحديثات آمن. يمكنها التعايش مع الحزمة القديمة أثناء النقل.
- انقل سجل المبيعات، المخزون، العملاء، الديون والمشتريات بعد **التحقق من النسخ الاحتياطي والاسترجاع**، فنسخ WebView وحدها ليست ضمانًا لتضمين قاعدة SQLite الأصلية.
- الترخيص القديم مخزن في بيانات التطبيق القديمة ومربوط بمعرّف التثبيت؛ لن ينتقل تلقائيًا عند تغيير الحزمة والتوقيع، ويجب **إعادة إصداره مرة واحدة من تطبيق التفعيل الأصلي** لمعرّف النسخة المستقرة الجديدة أو استخدام خدمة ترحيل مصادق عليها.
- توليد مفتاح التوقيع الجديد يجب أن يتم محليًا عند المالك وحفظ نسختين آمنتين وعدم رفع الملف أو كلمات المرور إلى المستودع العام. تخصيص أسرار GitHub Actions لمفتاح إصدار ثابت شرط أساسي.
- سير عمل النشر على GitHub يتوقف ما لم تُضبط صراحة `NOMAD_CUTOVER_APPROVED=true` بعد نجاح اختبارات النقل والتفعيل.
- لم يتم تجميع APK رسمي أو اختباره على هاتف/نشره في GitHub Releases بعد؛ نشر مسودة لا يجعل إشعار التحديث يظهر في 1.2.19.

**ترتيب الخطوات:** نسخة احتياطية قديمة مؤكدة → إنشاء مفتاح ثابت → بناء APK جديد → تثبيت متوازٍ واختبار الاستعادة → إعادة إصدار التفعيل → اختبار التحديث اللاحق بالتوقيع ذاته → نشر الإصدار وبيان آخر نسخة.
